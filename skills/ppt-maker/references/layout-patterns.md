# 그림·글 조합 패턴

사용자가 "이렇게 만들어 달라"고 준 레퍼런스 장표(2026-10-14, 두 묶음 25장)에서 **글과 그림을 어디에, 어떻게 엮었는지**만 뽑아 적은 문서다.
레퍼런스 이미지는 저장하지 않는다. 다음 덱을 만들 때 이 문서의 구성 방식을 응용한다.
블록 필드 형식은 `outline-schema.md`, 블록 고르는 순서는 `block-choice.md`.

## 0. 레퍼런스에서 읽은 공통 원칙

1. **제목은 결론 한 줄, 강조 구절만 포인트 컬러.** "…없는 **센싱 및 안전관리 시스템 도입 필요**". 제목 아래 회색 한 줄은 근거·범위.
2. **글의 위계는 크기·굵기 두 단계로 끝낸다.** 작은 회색 보조 한 줄 → 큰 제목(두 줄이면 둘째 줄만 굵게) → 짧은 설명. 세 단계를 넘기지 않는다.
3. **그림은 장식이 아니라 내용의 짝이다.** 카드 하나에 그림 하나, 그림이 그 카드의 메시지를 대신 말한다. 그림이 없는 카드와 있는 카드를 한 줄에 섞지 않는다.
4. **본문 위·아래에 "띠"를 붙여 장표를 닫는다.** 아래에는 결론 한 문장 띠, 대상별 요약 띠(행정 | 주민), 지표 띠(주요 평가 지표 | a | b | c), 흐름 띠(① → ② → ③). 위에는 공통 데이터 띠(하나의 데이터 | 소음 수준 | 소리 유형 | …).
5. **흐름은 화살표 하나로 방향을 준다.** 비교 → 결과, 단계 → 단계 사이에 작은 화살표(›, ▶)를 두고, 화살표 뒤 칸을 연한 포인트 컬러로 칠해 "도착점"을 표시한다.
6. **강조 칸은 하나만.** 비교 중 우리 쪽(오른쪽·마지막 열), 단계 중 현재, 결과판 — 한 장에 강조 칸 하나.
7. **숫자는 크게 하나, 근거는 작게 옆에.** "민원 약 60% 감소" 큰 글자 + 작은 막대 2개 + 회색 출처 한 줄.

## 1. 글 + 그림

### 1-1. 일러스트 카드 격자 → `figcards` (`layout:"side"`)
- **구성**: 흰 카드 4장(2×2) 또는 3장. 카드 왼쪽 55%에 글, 오른쪽 45%에 그림.
- **글 위치**: 세로 가운데. 위에서부터 작은 회색 보조 한 줄(선택) → 큰 제목 두 줄, **둘째 줄만 굵게**("실시간 사고감지 / **골든타임 확보**").
- **그림 위치**: 카드 오른쪽 아래 모서리에 붙인다. 배경 없는(누끼) 인물·사물 일러스트가 카드 가장자리에서 살짝 올라온 느낌. 그림 위아래가 카드 테두리와 맞닿아도 된다.
- **언제**: 대등한 효과·필요성·요구 3~4개를 "한 장면씩" 기억시키고 싶을 때. 글이 두 줄을 넘으면 이 패턴이 아니다.
- **그림 고르기**: 네 장 모두 같은 그림체·같은 인물(예: 같은 작업자의 다른 동작). 서로 다른 그림체를 섞지 않는다.

### 1-2. 상황 사진 3열 → `figcards` (`layout:"top"`) + `strip`
- **구성**: 세 칸. 칸마다 위 사진(칸 높이의 절반, 꽉 채워 자름) → 질문형 제목("누구를, 언제 단속할 것인가?") → 회색 설명 두 줄 → **포인트 컬러 결론 한 줄**("도착 전 상황 종료"). 칸 사이는 세로 구분선이거나 카드.
- **아래 띠**: 대상별 요약 두 칸 — 큰 포인트 컬러 키("행정", "주민") + 한 줄 설명. `strip` 의 `{k, v}` 항목.
- **언제**: 문제 정의. "세 가지 결정·세 가지 어려움"처럼 장면이 다른 문제 3개.
- **글 맞추기**: 세 칸의 제목·설명·결론 글 길이를 비슷하게. 결론은 6~12자.

### 1-3. 단계 일러스트 카드 → `figcards` (`layout:"top"`, `arrows:true`, `head`, `foot`) + `flow`
- **구성**: 카드 3장을 › 로 잇는다. 카드마다 맨 위 칩 "01 | 현재"(번호 + 시점) → 그림(개념 일러스트) → 굵은 제목 → 회색 한 줄 → (불릿 2~3개) → 맨 아래 회색 띠 "활용 | …" / "목표 | …".
- **아래 띠**: 아이콘(또는 번호) 흐름 띠 "지표 고도화 과정 | ① 데이터 축적 → ② 공동연구 → ③ 지표 개발 → ④ 서비스 반영". `flow` 의 `label` + `steps`.
- **언제**: 현재 → 중기 → 장기 로드맵, 시점마다 하는 일과 목표가 다를 때. 기간이 겹치면 `gantt`.

### 1-4. 제품 해부도 → `annotate` (+ 아래 `flow`)
- **구성**: 연회색 판 하나. 왼쪽 24%에 글: 작은 회색 보조("감지된 이상징후를 파악하는") → **큰 제품명 두 줄, 둘째 줄 포인트 컬러**("휴대용 / **초음파 카메라**") → 가는 선 → 사양 불릿 3~4개(무게·배터리·센서).
- **그림**: 오른쪽에 제품 사진 1~2장(앞면·뒷면), 사진 위에 작은 회색 캡션("카메라 전면"). 부위마다 점 → 가는 선 → 둥근 이름표(pill). 이름표는 사진 바깥쪽으로 빼서 사진을 가리지 않게.
- **아래 띠**: 동작 순서 STEP 01~05 상자 띠(`flow`).
- **언제**: 장비·기기·화면의 부위별 기능을 보여 줄 때. 사진은 배경을 지운 누끼가 가장 좋다.
- **점 좌표**: `pins[].x·y` 는 그림 상자 안 %(왼쪽 위 0,0). 이름표 자리 `lx·ly` 를 안 주면 가까운 바깥쪽으로 자동으로 뺀다. 한 사진에 점 3~5개.

### 1-5. 두 대상 화면 목업 (하나의 데이터 → 두 사용자)
- **구성**: 위 띠 "하나의 관측 데이터 | 소음 수준 | 소리 유형 | 관측 위치 | 발생 시간"(`strip`) → 두 갈래 화살표 → 왼쪽 카드 "주민 | 생활 속 소음 확인"(폰 화면 + 기능 3개 아이콘 목록 + 말풍선 질문), 오른쪽 카드 "행정 | 근거 기반 대응"(모니터 화면 + 기능 3개 + 말풍선) → 아래 흐름 띠(`flow`).
- **지금 만드는 법**: `strip` + `columns` 2개(칸마다 `image` 에 화면 목업, `items` 에 기능 3개, 말풍선 질문은 `text`) + `flow`. 갈래 화살표는 아직 없다.
- **언제**: 같은 기능을 쓰는 사람이 둘(B2C·B2G, 사용자·관리자)일 때.

### 1-6. 지도·구성도 비교
- **구성**: 왼쪽 좁은 칸(기존 방식, 그림 작게) / 오른쪽 넓은 칸(우리 방식, 그림 크게). 칸 제목 아래 **가격·규모를 큰 포인트 컬러 숫자**로("약 7,000만원 / 대" vs "약 1,500만원 / 대"). 그림 아래 주석 3칸, 오른쪽엔 번호 단계 띠. 맨 아래 "주요 평가 지표 | a | b | c | d" 띠 + 결론 한 문장.
- **지금 만드는 법**: `columns`(`flex` 1 : 1.8, 칸마다 `stat` + `image` + `items`) + `strip`(label + items) + `callout`(tone `strong`).
- **그림 너비 차이가 곧 메시지**다(좁은 관측 vs 넓은 관측). 두 그림을 같은 크기로 두지 않는다.

### 1-7. 증빙 띠 + 표
- **구성**: 위에 인증서·특허증 썸네일을 한 줄로 나열한 어두운 띠(제목 "공신력 및 네트워크" + 아래 한 줄 설명), 아래에 특허·상표 목록 표.
- **지금 만드는 법**: `image`(`side:"full"`, 썸네일을 한 장으로 합친 그림, `flex` 1) + `table`(`flex` 1.2).

### 1-8. 표 안 그림 행
- **구성**: 비교표 첫 줄을 "공급 방식 개요도" 그림 행으로. 마지막 열(우리)은 진한 머리글 + 연한 바탕으로 강조. 표 아래 아이콘 카드 3개 + 현재/확장 띠 + 결론 띠.
- **지금 만드는 법**: 그림 행은 아직 없다. `table`(emphasize 마지막 열) + `cards` 3개 + `strip` + `callout`. 그림이 꼭 필요하면 표 위에 `columns` 3칸 `image` 를 따로 둔다.

## 2. 글 + 숫자·그래프

### 2-1. 번호 카드 + 큰 숫자 + 작은 그래프
- **구성**: 카드 3장, 카드마다 "01 주민 불편 변화" 머리 → 아이콘 + **큰 숫자**("민원 약 60% 감소") → 회색 근거 → 작은 막대 2개(이전 100 / 이후 40) → 회색 주석. 아래 "기대 가치" 아이콘 띠 + 출처가 붙은 사례 배너.
- **지금 만드는 법**: `columns` 3칸(`stat` + `chart` 또는 `items`) + `strip` + `callout`.

### 2-2. 그래프 두 판
- **구성**: 왼쪽 넓게 꺾은선(두 시리즈, 끝 값만 크게 표기, 연평균 성장률 말풍선), 오른쪽 위 100% 누적 막대(구성비), 오른쪽 아래 가로 막대(성장률). 각 판 아래 결론 한 줄 배너. 맨 아래 사례 띠 + 결론 문장.
- **지금 만드는 법**: `columns`(`flex` 1.4 : 1, 칸마다 `chart`) + `strip` + `callout`. 누적 막대는 아직 없다.

### 2-3. 세로 구분선 3열 (카드 없이)
- **구성**: 흰 바탕에 세로 줄로만 나눈 3열. ① 라벨–값 목록(왼쪽 라벨 포인트 컬러, 오른쪽 설명), ② 큰 수치 + 막대 2개, ③ 소제목 + 설명 두 묶음. 아래 결론 배너.
- **지금 만드는 법**: `columns` 3칸(① `rows`, ② `stat` + `chart`, ③ `sections`). 카드 없는 버전은 아직 없다.

### 2-4. 조사 결과 대시보드
- **구성**: 위 "조사 개요" 띠(대상·방법·수단·질문), 가운데 3판(가로 막대 응답률 / 항목별 금액 막대 / 해석 번호 목록), 아래 기준선 막대(현재 대비 위치), 맨 아래 결론 박스 2개.
- **밀도가 높다.** 제출·열람용(dense) 덱에서만. 발표용이면 2장으로 나눈다.
- **지금 만드는 법**: `strip`(개요) + `columns` 3칸(`chart`, `chart`, `items`) + `columns` 2칸 결론.

## 3. 글만 (구조)

### 3-1. 비교 → 결과 → `compare` + `result`
- **구성**: 왼쪽 두 칸을 나란히 붙인다 — 기존(회색 머리띠) / 우리(포인트 컬러 머리띠, 칸 전체 연하게). 칸마다 같은 기준("현장", "기계 및 설비") 줄을 맞춘다. 굵은 화살표 → 오른쪽 결과판(연한 포인트 컬러 바탕): 큰 제목 "예방 및 현장대응 효율 증대" + 번호 줄 4개(01 제목 / 회색 한 줄).
- **언제**: "A만 쓰던 것에 B를 더하면 → 이런 효과". 비교만 있고 효과가 없으면 `compare`, 효과만 있으면 `cards`.

### 3-2. 질문·답 격자 → `qa`
- **구성**: 2열 × 3행 카드. 카드마다 "**Q.**"(포인트 컬러) + 굵은 질문 한 줄 → 회색 답 2~3줄, 답 속 핵심 구절만 굵게·포인트 컬러.
- **언제**: 부록의 예상 질문, 투자자·심사위원 우려 사항. 질문은 상대방 말투 그대로("…않나", "…나오나").

### 3-3. 단계 카드 + 시점 라벨 + 근거 3열
- **구성**: 위 4단계 카드(카드 머리 "T+수초 — 지향", 굵은 동사형 제목 "카메라가 본다", 설명, 맨 아래 작은 회색 상태 줄), 단계 사이 화살표, 하나만 강조 테두리. 아래 연한 판에 "실행 인프라는 이미 깔려 있습니다" 소제목 + 근거 3열. 맨 아래 결론 한 문장.
- **지금 만드는 법**: `process`(steps 4, `period` 에 시점, 강조 하나 `highlight`) + `columns` 3칸 + `callout`.

## 3+. 두 번째 레퍼런스 (2026-10-14, 10장)

같은 날 두 번째로 받은 레퍼런스 10장에서 읽은 구성이다. 첫 묶음보다 **여백이 넓고 요소 수가 적다.** 발표용(airy) 덱에서 특히 쓴다.

### 3-4. 원형 단계도 → `process` (`style:"circle"`)
- **구성**: 같은 크기의 원 3~5개를 가로로 놓고, 원 사이를 점선 화살표(···▶)로 잇는다. 원은 테두리만(가는 진한 선), 바탕은 흰색.
- **원 안**: 맨 위 작은 아이콘이나 번호(포인트 컬러) → 굵은 단계 이름 → 회색 설명 두 줄. 가운데 정렬.
- **제목**: 위쪽 가운데에 작은 영문 라벨(PROCESS) + 큰 두 줄 제목. 우리 덱에서는 장표 위 제목 자리가 그 역할을 한다.
- **언제**: 시스템 구성도, 처리 순서. 단계마다 설명이 두 줄 이하일 때만. 길면 `process` 기본형.
- 강조할 단계 하나는 `highlight`(테두리가 포인트 컬러).

### 3-5. 화살표 머리띠 단계 + 완료 기준 → `process` (`style:"chevron"`, `done`) + `strip`
- **구성**: 맨 위 갈매기(›) 모양 머리띠 3개를 이어 붙인다. 머리띠 색은 **연함 → 메인 → 진함**으로 진행감을 준다. 머리띠 안: 큰 번호 + 굵은 단계 이름 + 작은 기간("약 2주", "D1 ~ D3").
- **가운데**: 단계마다 흰 카드. 굵은 결론 제목("2주 내 설치 준비를 완료합니다") + 불릿 4개, 불릿 속 핵심 구절만 포인트 컬러.
- **아래**: 단계마다 진한 띠 "완료 기준 : **반입 승인·장비 입고**". 맨 아래 흰 띠 "산출물 4종 | a · b · c · d".
- **언제**: 도입 일정·온보딩처럼 단계마다 할 일과 끝났다고 말할 기준이 있을 때.

### 3-6. 큰 숫자 영웅 패널 → `bigstat`
- **구성**: 세 열. ① 연한 포인트 컬러 패널 안에 제목("외부 데이터 유출") → **아주 큰 숫자**("0%", 단위는 작게) → 회색 근거 → 굵은 결론 두 줄(핵심만 포인트 컬러). ② 수치 3개를 가는 선으로 나눈 목록: 큰 포인트 컬러 숫자("<300ms") → 회색 측정 조건 → 굵은 의미 한 줄("개발 흐름이 끊기지 않습니다"). ③ 굵은 소제목 두 줄 + 흰 사양 카드 4개(키 포인트 컬러 + 회색 설명).
- **언제**: 성과·기대 효과. "가장 센 숫자 하나 + 받쳐 주는 숫자 셋 + 근거 사양". 숫자마다 **의미 한 줄**을 반드시 붙인다.

### 3-7. 진행 막대 카드 → `cards` + `bar`
- **구성**: 카드 2장. 카드마다 "Step 01" 알약 → 굵은 제목 → 회색 설명 → 아래쪽에 큰 퍼센트 + 오른쪽 라벨("의사결정 기간 단축") → 둥근 진행 막대 → 가는 선 + 가운데 포인트 컬러 한 줄.
- **언제**: 정책·방법마다 대표 효과가 퍼센트 하나로 말해질 때. 막대 길이가 곧 숫자이므로 0~100% 값만.

### 3-8. 묶음 단계 카드 (아직 블록 없음)
- **구성**: 큰 단계 4개(기획·가공·검수·완료)를 진한/메인 색이 번갈아 드는 머리띠 카드로, 카드 안에 작은 STEP 상자 1~2개(아이콘 + "STEP 1" + 한 줄). 카드 사이 → 화살표.
- **지금 만드는 법**: `figcards`(`layout:"top"`, `arrows:true`, `head`)에 그림 대신 `items` 로 STEP 을 적거나, `process` 기본형 + `items`. 세부 단계가 7개 넘으면 이 패턴.

### 3-9. 가운데 아이콘 카드 (아이콘 미지원)
- **구성**: 넓은 흰 카드 2장, 카드 가운데 위에 선 아이콘 → 굵은 두 줄 제목 → 회색 설명 세 줄. 모두 가운데 정렬. 위에는 가운데 정렬 큰 제목 + 회색 한 줄.
- **지금 만드는 법**: `figcards`(`layout:"top"`) — 그림 자리에 아이콘 그림을 넣는다. 아이콘 묶음(선 아이콘 세트)은 아직 없다.

### 3-10. 성장 곡선 + 수상 (어두운 바탕)
- **구성**: 어두운 그라데이션 바탕. 왼쪽 위 수상 배지 3개(월계수 + 두 줄 글) → 불릿 3개(첫 줄 숫자만 포인트 컬러). 오른쪽으로 가로지르는 굵은 곡선, 연도마다 점 + **큰 흰 숫자** + 작은 연도, 마지막 점만 크게·포인트 컬러·빛. 오른쪽 아래 회사 정의 세 줄(마지막 줄만 흰색 굵게).
- **지금 만드는 법**: 본문 장표는 밝은 바탕이라 그대로는 못 만든다. `chart`(line, 시리즈 하나, `emphasis`) + 왼쪽 `columns`(`image` 배지 + `items`)로 비슷하게. 회사 소개서 첫 장에 쓰기 좋다.

### 3-11. 탭 표시 + 큰 사진
- **구성**: 가운데 큰 제목 아래 점선 위에 원 3개(현재 탭만 채운 원) + 탭 이름 → 아래 연회색 판 위 큰 사진.
- **지금 만드는 법**: 장표는 넘겨 보는 매체라 탭이 동작하지 않는다. 탭마다 한 장씩 만들고, 위에 `flow`(현재 단계만 강조) + 아래 `image`(`side:"full"`)로 "지금 몇 번째인지"를 보여 준다.

### 3-12. 행동 유도 상자 (마무리)
- **구성**: 메인 컬러 그라데이션 바탕 위 흰 큰 두 줄 문장 → 가운데 흰 상자: 굵은 한 줄 + 체크 표시 3개(전문 컨설팅 · 무상 PoC · 무제한 A/S) + 진한 버튼("소개서 다운로드 ↓").
- **지금 만드는 법**: 마무리 장표(`closing`)는 렌더러가 그린다. 본문 마지막 장에 쓰려면 `callout`(tone `strong`, 결론 한 줄) + `strip`(체크 항목 3개).

## 4. 띠 (모든 패턴에 붙이는 부품)

| 띠 | 블록 | 모양 | 쓰는 자리 |
| --- | --- | --- | --- |
| 결론 한 문장 | `callout` (tone `strong` 또는 기본) | 장표 너비 전체, 가운데 큰 글 한 줄 | 맨 아래 |
| 대상별 요약 | `strip` items `{k, v}` 2~3개 | 큰 포인트 컬러 키 + 설명, 세로 줄로 나눔 | 맨 아래 |
| 지표·항목 나열 | `strip` label + items | "주요 평가 지표 \| a \| b \| c" | 맨 아래 / 맨 위 |
| 흐름 | `flow` label? + steps | 상자 › 상자 › 상자 | 맨 아래 |
| 공통 데이터 | `strip` label + items | "하나의 데이터 \| …" | 맨 위 |

띠는 높이가 내용만큼이라 본문 블록이 남는 공간을 다 쓴다. 한 장에 띠는 두 개까지(예: `strip` + `callout`).

## 5. 다음 덱에 응용하는 순서

1. `block-choice.md` 순서로 주 블록을 먼저 고른다.
2. 그 장표에 **그림이 메시지를 대신할 수 있으면**(장면·인물·제품·화면) 이 문서의 1절 패턴으로 바꾼다. 원문에 그림이 없으면 `image`·`alt` 에 어떤 그림이 들어갈지 적고 `[입력 필요]` 목록에 올린다. 그림 경로는 지어내지 않는다.
3. 장표 아래에 4절의 띠를 붙일 수 있는지 본다. 결론이 있으면 결론 띠, 대상이 둘이면 대상별 요약 띠, 순서가 있으면 흐름 띠.
4. 덱 전체에서 1절(그림) 패턴이 3장 연속이면 하나를 2·3절 패턴으로 바꾼다.
