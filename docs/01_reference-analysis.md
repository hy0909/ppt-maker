# 발표자료 문법 규칙

덱 엔진과 디자인 설계에 반영한 발표자료 문법. 다양한 실제 발표 사례를 분석해 추출한 구조와 길이 한계.

---

## 장표 문법 (모든 본문 장표 공통)

실제 발표자료를 분석해 보면, 효과적인 슬라이드는 네 계층의 명확한 순서를 따른다.

```
┌ 헤더 (좌상단)           "N. 섹션명 – 소제목"
├ 리드 메시지 박스       1~2문장 결론 요약, 선행 조건 또는 집계 범위
├ 컬럼 헤더 ×2~3         "1. 소주제", "2. 소주제" 등 잘린 모서리 박스
└ 컬럼 본문             카드 / 도식 / 표 / 이미지 / 수치 강조
```

### 제목과 리드 라인 관계

- 제목이 "무엇"을 말하면, 리드 라인은 "그래서 결론은 무엇"을 말한다.
- 제목 + 리드 메시지만으로도 그 슬라이드의 주장이 읽혀야 한다.
- 리드 메시지는 항상 있어야 한다.

### 컬럼 구성

- 개수: 2~3개 (섹션과 주장에 따라)
- 구조: 각 컬럼은 소제목 + 도형/카드
- 흐름: 프로세스는 좌→우 화살표, 산출물은 둥근 사각형으로 표기

### 정보 밀도

- 심사 대상 발표(평가자가 근거를 꼼꼼히 읽음): **고밀도 모드 — 한 장에 근거를 모두 담는다.** 도형 28~84개 범위.
- 경영진 보고 또는 컨퍼런스 발표(청중이 말을 들으며 슬라이드를 훑음): **저밀도 모드 — 핵심만, 여백 충분.** 16pt 본문 이상.

덱 제목과 목적에 따라 밀도 모드를 선택한다.

---

## 색상과 시각 토큰

### 색 관리

- 주색(primary): 제목 배경, 버튼, 강조 텍스트. 명도 조정으로 계층화 (어두운 버전 → 밝은 버전)
- 보조색: 경고, 긍정, 중립 상태 구분
- 배경: 흰색 기본. 마스터 레이아웃 없이 '빈 화면' 모드 사용

### 폰트 크기 가이드

| 용도 | 고밀도 | 저밀도 |
| --- | --- | --- |
| 표지 제목 | 28~40pt | 40pt+ |
| 섹션 헤더 | 18~20pt | 28pt+ |
| 슬라이드 제목 | 30pt | 36pt+ |
| 리드 메시지 | 16pt | 18pt |
| 본문 | 12~14pt | 16pt+ |
| 표·카드 텍스트 | 10~11pt | 12~14pt |

---

## 도형과 아이콘

- 프로세스: 사각형 또는 원 → 화살표 → 다음 단계
- 산출물: 둥근 사각형 (모서리 반지름 8~12pt)
- 데이터/표: 가는 선 표, 강조 열은 배경 색상 또는 배지
- 이미지: `object-fit: contain`으로 원본 가로세로 비율 보존

---

## 구조 결정: 밀도 모드 두 가지

### 1. Dense (고밀도, 기술 심사 중심)

- 목표: 심사위원이 슬라이드만 읽고도 근거와 기술을 판단
- 텍스트: 12~14pt, 도형 다수, 정보 밀집
- 여백: 최소 (안전 여백만)
- 대상: 과제 발표, 제안서, 연차보고서, 정책 문서

### 2. Airy (저밀도, 발표·경영진 중심)

- 목표: 청중이 말을 들으며 시각적 정보를 빠르게 파악
- 텍스트: 16pt 이상, 도형 적음, 여백 충분
- 여백: 충분 (시선 안내, 숨 쉬기)
- 대상: 컨퍼런스 발표, 경영진 보고, 세일즈 피치

문서 유형에 따라 기본 밀도를 정하되, 사용자가 바꿀 수 있게 한다.

## 길이 한계

| 항목 | 한계 | 근거 |
| --- | --- | --- |
| 표지 제목 | ~16자 | PDF 단 한 줄에 읽혀야 함 |
| 슬라이드 제목 | 6~52자 (중앙값 32자) | 30px에서 두 줄을 넘으면 여백 침범 |
| 리드 메시지 | 1~2문장 (80자 이내) | 박스 안에 한눈에 읽혀야 함 |
| 표 셀 | 1줄 (셀 폭의 2~3배) | 셀 폭이 좁으므로 줄바꿈 금지 |
| 컬럼 수 | 2~3개 | 3개 초과 시 텍스트 크기 14pt 이하로 떨어짐 |

## 토대: 표준 덱 엔진

이 규칙은 HTML 슬라이드 템플릿 위에 세워졌다. 템플릿은 `deck-stage.js` 엔진(슬라이드 렌더링, 페이지 나누기, 핸드아웃 PDF 생성)과 `deck-editor.js`(브라우저 WYSIWYG 편집)를 포함한다.

주요 설계 결정:

- **PDF 렌더링**: 헤드리스 Chrome이 `@page 1280×720` 크기로 슬라이드 하나당 한 페이지씩 PDF를 만든다.
- **PPTX 변환**: 같은 HTML을 PPTX 호환 라이브러리로 변환한다. 몇몇 CSS 속성 (`box-shadow` 등)은 쌍곡선처럼 PPTX에서 예상과 달리 렌더되므로, 생성 규칙에서 이를 강제한다.
- **미리보기**: 브라우저에서 HTML을 열면 썸네일 레일이 표시되고, `E` 키로 편집 모드 전환도 가능하다.
